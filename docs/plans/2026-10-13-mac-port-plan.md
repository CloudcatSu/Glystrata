# Glystrata Mac 版（Apple Silicon）移植計畫

- 建立：2026/10/13
- 分支：`mac-port`
- 對照基準：Windows 版 v1.2.3（commit `04ff0b4`）

## 1. 已定案的決策

| 項目 | 決定 |
| --- | --- |
| 技術路線 | Swift 原生重寫，不走 Avalonia、不走 Avalonia XPF |
| 介面技術 | SwiftUI 為主；編輯器本體用 AppKit 的 `NSTextView`（中文輸入法交給系統） |
| 一致的範圍 | 版面、配色、功能與 Windows 版一致 |
| 照 Mac 慣例的部分 | 字型（蘋果預設字型）、選單位置、視窗按鈕、視窗大小調整；不做 Snap Layouts |
| 隱藏快照檔 | 用 Mac 的隱藏旗標（`URLResourceValues.isHidden`），檔名維持 `<檔名>.gss` |
| 程式位置 | 同一個 repo，Mac 版全部放在 `mac/` |
| 發布 | 目前只自用（ad-hoc 簽章）；Apple Developer 帳號之後才申請 |
| 最低系統版本 | macOS 14 |
| 閱讀器的冷門語法 | `H~2~O`、`x^2^`、`++插入++`、`==標記==` 的顯示要跟 Windows 版一樣 |
| Windows 版既有問題 | Mac 版遇到就修，並記在 `docs/reviews/2026-10-13-windows-issues-found-during-mac-port.md`，之後帶回 Windows 版處理 |
| 建置方式 | XcodeGen：`mac/project.yml` 進版控，Xcode 專案檔由它產生、不進版控 |
| 快速鍵 | 照 Mac 慣例：Ctrl 換成 ⌘、Alt 換成 ⌥；取代 ⌥⌘F、重做 ⇧⌘Z、新增群組 ⇧⌘N。對照表在 `mac/Sources/GlystrataCore/Commands/AppCommands.swift` |
| 閱讀器的 emoji | 用蘋果系統的彩色 emoji，不帶 Twemoji 圖檔 |

## 2. 專案結構

```text
mac/
├── Package.swift              ← 核心邏輯的 Swift 套件
├── Sources/GlystrataCore/     ← 不含介面的邏輯（對應 src/Glystrata.Core，外加介面文字、指令表、語法分色規則）
├── Tests/GlystrataCoreTests/  ← 對應 tests/Glystrata.Verification
├── project.yml                ← XcodeGen 設定，產生 App 的 Xcode 專案
├── App/                       ← SwiftUI／AppKit 介面
└── scripts/build.sh           ← 產生專案並建置 App
```

需要 Xcode 27 與 XcodeGen（`brew install xcodegen`）。

```bash
cd mac
swift test            # 跑核心邏輯的測試
scripts/build.sh      # 建置 App，結束時印出 .app 的位置
```

開發版 App 另有兩個啟動參數，用來產生比對用的畫面：`-GlystrataSnapshotPath <檔案.png>` 會在啟動幾秒後把主視窗存成圖檔並結束，`-GlystrataTheme light|dark` 指定該次執行的主題。

### 3-2 實際操作測試（2026/10/13，用 Computer Use 操作隔離的測試實例）

操作後結果正確：

- 點 TAB 切換、左右分割、狀態列跟著切換的文件更新
- 打字、Enter 續行清單、`->` 自動換成 `→`、緊接著按 Backspace 還原、復原與重做、自動儲存寫回檔案
- ⌘F 開尋找與取代、「取代」只換目前這一個、「全部取代」一次換完且復原一次就整批還原
- ⌘, 開偏好設定、勾「顯示文字編輯快捷列」按套用後主視窗立刻出現工具列、設定檔有寫入
- 格式工具列的粗體按鈕
- 新增群組（側欄的＋與 ⇧⌘N）
- TAB 右鍵選單八個項目都在；「立即建立快照」有產生 `.gss`；「移動到群組」會更新群組與 TAB 的歸屬
- 結束時有未儲存文件會詢問；「取消」留在 App，「不儲存」正常結束且工作階段有存檔
- 外部變更選「重新載入」而文件有未儲存修改時會再確認一次：按「取消」本機內容與未儲存標記都保留、磁碟上的檔案沒被動到；按「重新載入」才換成磁碟上的內容
- 檔案寫不進去時（資料夾唯讀），儲存失敗的提示只跳一次，TAB 保留未儲存標記
- 檔案被移走後，狀態列顯示「檔案已被刪除或移走，儲存時會重新建立」，不跳對話框；再打字，自動儲存把檔案建回來，狀態列恢復

測試中發現並修掉：

- 系統提供的選單（檔案、編輯、復原、結束…）固定顯示英文：App 沒有宣告語系。已加 `CFBundleAllowMixedLocalizations`
- 新增與重新命名群組的對話框把標題顯示兩次

工具模擬不了、需要親手測：

- 拖曳 TAB 排序、拖曳群組排序、把 TAB 拖到群組、把檔案從 Finder 拖進視窗（模擬拖曳試了兩次都沒有換位置，分不出是工具還是 App 的問題）
- 群組的右鍵選單與顏色
- 注音輸入、⌘＋滾輪與觸控板兩指縮放
- 快照歷史、比較、閱讀器視窗裡的按鈕
- YAML 檔裡打 `->`、`--` 不會被換成符號（背景的測試實例收不到鍵盤事件，只通過建置）
- 自動儲存正要寫檔時才發現外部變更的情境（時間差在 1 秒內，工具抓不準）

對照 Windows 版後的結論：

- 格式工具列在 YAML 檔上方也會出現：Windows 也是，維持
- 「全部取代」不分大小寫：Windows 也是（`FindReplaceWindow.xaml.cs:118`），維持
- 從 Finder、開檔對話框、拖放開的檔案都會歸入目前的群組並寫進群組的檔案清單（Cloud 決定；Windows 從 Finder 開的不寫進清單）
- TAB 右鍵選單改成「在 Finder 中顯示」（Cloud 決定）
- Windows 之後也改成從檔案總管開的檔會寫進群組清單，兩邊一致（Cloud 決定，由 Windows session 轉述）

### 3-3 與 Windows 參考截圖比對（2026/10/13）

截圖在 `windows-reference` 分支的 `docs/reference/windows-1.2.3/`，亮暗各 40 張。亮色整套都看過；暗色看過主視窗（01、03–05）、編輯器（18、19）、偏好設定（20、21）、比較（26）、尋找與取代（27）、語法說明（28）、閱讀器（29-1），其餘暗色畫面用的是同一組版面與色票，沒有逐張看。選單與系統對話框在 Mac 上由系統繪製，暗色不比對。

比對後修掉的：

- 行號右邊的點狀分隔線、行號與內文同字級
- 格式工具列移到 TAB 列上方
- 閱讀器：文字下方緊接 `---` 時顯示為文字，不畫分隔線
- 自動儲存寫檔前先確認檔案沒被其他程式改過
- 側欄群組列：縮排與列高照 Windows 的樹狀列（色條在 x=31、每列 35），選取底色改成直角
- 工具列與側欄的「＋」改用細線畫，粗細與旁邊的圖示一致；側欄的「＋」改成次要文字色
- 窗格沒有記錄選哪個 TAB 時（還原工作階段、關掉目前的 TAB）選第一個，原本選最後一個

已一致、不用改的：主視窗版面與側欄寬度、TAB 與群組色條、各選單項目、TAB 與群組右鍵選單、快照歷史、比較視窗、尋找與取代、閱讀器的標題／清單／核取方塊／連結／程式碼／分隔線／缺圖提示／Emoji、分割時搬走最後一個 TAB、裸網址的連結規則、軟換行顯示為換行。

看得出差別、但沒有改的：

- 編輯器行距：Windows 用 Cascadia Code，每行約 16.4；Mac 用系統等寬字，每行 17，同樣高度的視窗少顯示約 4% 的行數
- TAB 列放不下時 Windows 在下方顯示捲軸，Mac 不顯示（可用觸控板或滾輪橫向捲動）
- 窗格的直向捲軸 Windows 一直顯示，Mac 照系統設定
- 暗色與亮色的色碼兩邊相同；截圖取到的數值差 1 是色彩描述檔換算的誤差

刻意與 Windows 不同的列在 `docs/reviews/2026-10-13-windows-issues-found-during-mac-port.md` 第 6 節。

還沒比對：亮色的 01、03–06、09、10、18、19、22–24、28，以及暗色整套。

還沒做：拖曳時被拖的項目變淡（Windows 有）；閱讀器裡連結的底線會多出一小段到後面的全形標點前。

待 Cloud 決定外觀取捨：偏好設定的分頁樣式、按鈕樣式、選色對話框（Windows 是自製樣式，Mac 版目前用系統原生）。

### 5-3 反向驗證
