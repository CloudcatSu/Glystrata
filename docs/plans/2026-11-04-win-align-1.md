# Windows 對齊第一批（分支 `win/align-1`，2026/11/04）

Mac 版（`mac-port` 分支）與 Windows 版同步實作的三項功能，這份文件記錄 Windows 這邊的做法、取捨與尚未做的部分，讓兩邊知道對方的狀態。版本號維持 1.2.3，發布時機由 Cloud 決定。

## 1. 閱讀器視窗獨立於主視窗

- `PreviewWindowManager.Toggle` 不再設定 `Owner`：閱讀器不跟著主視窗最小化或隱藏，不再永遠疊在主視窗上，工作列有自己的按鈕。
- 開啟位置（`Services/WindowPlacement.cs`）：先試主視窗右邊、再試左邊，兩邊都放不下就從主視窗左上角往右下錯開 40。主視窗最大化時視為佔滿螢幕，直接錯開。從獨立編輯視窗開的閱讀器以那個視窗為基準。
- 不記憶閱讀器位置（原本就沒有），也不在工作階段裡還原閱讀器。
- 關閉主視窗＝結束 App：`Window_Closing` 原本就會關掉所有閱讀器；另外把 `ShutdownMode` 改為 `OnMainWindowClose`，避免沒有擁有者的視窗讓程式留在背景。
- 切換主題、語言時照舊由 `PreviewWindowManager` 逐一更新。

## 2. 文件可以漂浮（最小版）

做法：獨立視窗（`Views/FloatingEditorWindow.cs`）只是一個外殼，裡面放的是和主視窗相同的 `EditorPaneControl`，由 `MainWindow.CreatePaneControl` 建立並接上同一套事件。一個檢視（`DocumentViewState`）的 `PaneId` 如果不屬於主視窗的窗格配置、而是某個獨立視窗的 pane id，它就在那個視窗裡。因此存檔、自動儲存、快照、群組顏色、重新命名、尋找與取代、閱讀器、多檢視同步都沿用原本的程式，沒有另做一套。

- TAB 右鍵：主視窗多了「在獨立視窗開啟」；獨立視窗的 TAB 右鍵改成「移回主視窗」（不顯示「在新窗格開啟」，分割只屬於主視窗）。
- 移回主視窗：放到主視窗目前的窗格最後面；如果側邊欄正在篩選某個群組、會把這個分頁藏起來，就切回「所有文件」。
- 「作用中的文件」：使用者在哪個視窗操作，選單與快捷鍵就作用在那個視窗的文件上（視窗被啟用時、以及在該視窗按快捷鍵時切換）。主視窗的狀態列一律描述主視窗自己選取的分頁。
- 新分頁一律開在主視窗：在獨立視窗按 Ctrl+N、Ctrl+O、Ctrl+Alt+N（新檢視）等，結果會出現在主視窗，並把主視窗帶到前面。
- 對話框跟著使用者所在的視窗：從獨立視窗觸發的提示、重新命名、快照紀錄、尋找與取代會以獨立視窗為擁有者，主視窗縮小時也看得到。檔案被外部修改的提示以「顯示這份文件的視窗」為擁有者（主視窗優先）。
- 已在獨立視窗開著的文件，再從檔案總管或最近清單開啟時，會把那個獨立視窗帶到前面，不會再開一份。
- 關閉獨立視窗＝關閉其中的分頁，走原本的「儲存／不儲存／取消」；取消時視窗保留。提示視窗還開著時又收到關閉要求（再按一次 X、Alt+F4）會忽略，避免視窗在自己的對話框底下被關掉。測試時出現過一次主視窗之後一直呈停用、點不動的情況，研判就是這個原因，已加上防護；加了之後連續送兩次關閉也正常。
- 「還原單一窗格」只合併主視窗的窗格，不會把獨立視窗的文件收回來。
- 側邊欄的群組篩選只影響主視窗，獨立視窗不受篩選。
- 縮放沿用主視窗的全域縮放（Ctrl+滾輪在任一視窗都會改全部編輯器），獨立視窗沒有自己的縮放滑桿。
- 拖曳檔案到獨立視窗會開在主視窗（與拖到主視窗相同）。

### 工作階段格式（與 Mac 共用）

`session.json` 新增 `floatingWindows`，每筆是 `{ "x", "y", "width", "height", "viewIds": [...] }`。檢視本身照舊列在 `views`，`viewIds` 只是說明哪些檢視在這個視窗裡；還原時這些檢視會放進新的獨立視窗，`views` 裡的 `paneId` 對獨立視窗沒有意義。

- 座標與大小是 WPF 的裝置無關單位（1/96 吋）；視窗最大化或最小化時記錄的是還原後的位置與大小。
- 只有已存檔的文件會被記錄（與主視窗相同），沒有任何已存檔文件的獨立視窗不寫入。
- 讀取時：寬高小於最小值就用預設大小；位置不在任何螢幕上（例如上次接的外接螢幕拔掉了）就改放到主視窗旁邊。還原的獨立視窗出現在主視窗後面，主視窗在前。
- 不認得的欄位一律忽略（`JsonStateStore` 沒有設定 `UnmappedMemberHandling`），`floatingWindows` 是 `null` 或某筆缺 `viewIds` 也不會出錯。驗證程式有一個測試用含未知欄位的檔案讀回。

### 先不做（後續項目）

- 拖曳 TAB 進出視窗、在視窗之間拖曳。
- 一個獨立視窗放多個分頁（資料結構已支援，介面沒有開放）。
- 獨立視窗自己的選單列與縮放滑桿。
- 閱讀器的位置記憶與工作階段還原。

## 3. 雙擊快照檔（Windows 補上，Mac 已有）

- `SnapshotFileAssociation.EnsureRegistered` 在既有的圖示登記之外，再寫入 `HKCU\Software\Classes\Glystrata.SnapshotFile\shell\open\command` = `"<Glystrata.exe>" "%1"`。仍然只在 `.gss` 沒有被其他程式佔用時才登記；每次啟動都會更新路徑，搬移 exe 後也正確。沒有碰其他副檔名，也沒有改系統預設程式。
- `SnapshotSidecarStore.GetSourcePathForSidecar`：去掉結尾的 `.gss`（不分大小寫）得到文件路徑，只有 `.gss` 的檔名不算。與 Mac 的 `sourcePath(forSidecar:)` 規則與測試案例相同。
- `MainWindow.OpenExternalPaths`（啟動參數、單一執行個體轉送都經過這裡）把 `.gss` 分開處理：文件已開著就切過去（在獨立視窗就帶那個視窗到前面），沒開就照「從檔案總管開啟」的方式開成分頁並加入目前群組，然後打開快照紀錄視窗。
- 旁邊沒有對應文件時顯示「找不到這份快照檔對應的文件」；內容其實是匯出的設定檔（`kind` 為 `glystrata-settings`）時，提示改用設定的「匯入設定檔…」。文字與 Mac 相同。
